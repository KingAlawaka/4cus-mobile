# 4cus

**Four people. One goal. Zero excuses.**

4cus is a minimalist accountability app. Users form groups of **max 4 people**
around a shared goal, post **daily photo check-ins** that peers verify, chat,
manage personal todo tasks with deadlines, and track phone usage for focus
coaching.

- **Groups** — public groups (listed on Discover so like-minded people can
  join) or private groups (join via 6-character invite code + share link).
- **Check-ins** — one photo per day per member; peers tap **Verify** to keep
  everyone honest.
- **Chat** — realtime group chat with text and photos.
- **Tasks** — personal short-term goals/todos with deadlines ("Today" and
  "Upcoming" views).
- **Focus** — Android: real screen-time via UsageStatsManager with a focus
  score and coaching; iOS/web: manual focus-session timer. Weekly charts
  drawn with `CustomPainter` (no chart dependency).
- **Design** — calm minimalism: warm-neutral background, single teal accent,
  16px rounded cards, generous whitespace, Material 3, system dark mode.

Built with Flutter for **Android, iOS and web**. Firebase Auth + Firestore +
Storage on the backend.

---

## Tech stack

| Layer | Choice |
|---|---|
| UI | Flutter, Material 3, `provider` |
| Auth | `firebase_auth`, `google_sign_in` (email + Google) |
| Database | `cloud_firestore` |
| Storage | `firebase_storage` (photos) |
| Media | `image_picker`, `share_plus` |
| Utils | `intl`, `uuid` |
| Native bridge | `MethodChannel` (`dev.fourcus/usage`) for Android usage stats |

No chart library — charts are hand-drawn `CustomPainter`s.

## Quickstart

```bash
# 1. Get dependencies
flutter pub get

# 2. Configure Firebase (replaces the TODO placeholders)
flutterfire configure   # see FIREBASE_SETUP.md for the full guide

# 3. Run
flutter run
```

Until `lib/firebase_options.dart` has real values, the app shows a friendly
"Firebase not configured" screen pointing at `FIREBASE_SETUP.md`.

## Key product rules

- Groups hold **at most 4 members** — enforced in a Firestore transaction
  and in the security rules.
- Check-in documents are idempotent per day: `{uid}_{yyyy-MM-dd}`.
- Users **cannot verify their own** check-ins.
- Usage-day documents are idempotent per day: `{uid}_{yyyy-MM-dd}`.

## Roadmap

- **On-device LLM coaching** — replace the static focus-score thresholds in
  `usage_service.dart` with a small on-device model (e.g. `flutter_gemma`)
  that generates personal milestones and coaching from local usage history,
  without sending user data to the cloud.
- Streaks and milestones for groups.
- Push reminders for unchecked-in members (FCM).
- Group analytics: weekly accountability report.
